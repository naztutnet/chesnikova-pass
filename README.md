# CHESNIKOVA PASS

Адаптивный веб-сайт для оформления гостевых пропусков в Amedia PassOffice. Один интерфейс работает на телефоне и компьютере: на мобильном используется нижняя навигация, на широком экране — постоянное боковое меню.

## Локальный запуск

Требуется Node.js 24+ (используется встроенный `node:sqlite`).

```bash
ALLOW_DEMO_AUTH=true PASSOFFICE_PROVIDER=demo npm start
```

Открыть `http://localhost:4173`.

## Текущий статус

- Реализован адаптивный пользовательский путь для телефона и компьютера.
- Добавлен свободный текстовый ввод: дата, место и несколько гостей разбираются в тот же редактируемый черновик, что и ручная форма.
- Поля прототипа сверены с формой разовой заявки PassOffice.
- Первый экран запрашивает персональные логин и пароль PassOffice. Пароль передаётся сервером только в PassOffice, не пишется в базу и не попадает в браузерное хранилище.
- Сервер хранит токены PassOffice только в оперативной памяти, выдаёт браузеру непрозрачную HttpOnly-сессию и защищает изменяющие запросы CSRF-токеном.
- Персональные данные заявки шифруются в SQLite; повторная отправка защищена ключом идемпотентности.
- Демо-провайдер позволяет проверить полный сценарий с настоящей проверкой входа, но без создания реального пропуска. В интерфейсе такой результат явно помечен как демо.
- Адаптер официального Open API заблокирован до получения Swagger, URL IntegrationServer и API-ключа конкретной установки.

## Публикация демо на GitHub Pages

```bash
npm run build:pages
```

GitHub Actions публикует содержимое `dist` после каждого push в `main`. Поскольку GitHub Pages не может безопасно принять пароль и запустить сервер, опубликованная страница только перенаправляет пользователя на HTTPS-сайт в Timeweb.

## Публикация веб-интерфейса на VPS

В корне проекта лежат `Dockerfile`, `compose.yaml` и конфигурация Caddy. Контейнер приложения запускает Node.js-сервер, Caddy публикует его на 80/443 и автоматически получает TLS-сертификат.

```bash
git clone https://github.com/naztutnet/chesnikova-pass.git /opt/chesnikova-pass
cd /opt/chesnikova-pass
cp .env.example .env
# Заполнить DATA_ENCRYPTION_KEY и APP_VERSION в .env, права файла — chmod 600.
docker compose up -d --build
docker compose ps
curl -fsS https://chesnikova-pass.201-24-48-93.sslip.io/api/health
```

Временный адрес без покупки домена задаётся через `SITE_ADDRESS`; по умолчанию используется `chesnikova-pass.201-24-48-93.sslip.io`. При подключении собственного домена достаточно изменить переменную и перезапустить контейнер:

```bash
SITE_ADDRESS=pass.example.ru docker compose up -d
```

Логины и пароли PassOffice никогда не входят в образ или `.env`: каждый пользователь вводит свои данные при первом входе. Для показа заказчику используется `PASSOFFICE_PROVIDER=demo`: вход проверяется настоящим PassOffice, а отправка заявки не изменяет портал. Реальное создание включается только после проверки контракта заявки на этой установке PassOffice.
